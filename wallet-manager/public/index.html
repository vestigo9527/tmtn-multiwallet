一句话结论

币安 Agentic Wallet 用网卡 MAC 认设备：同一块网卡只能挂一个币安账号的会话，登第二个会把第一个挤掉。TMTN 的多钱包方案就是「一个钱包 = 一个独立 MAC = 一个独立 ~/.baw 登录目录」。

三层隔离怎么搭

层做法目的
设备身份容器用 mac_address: 02:xx:… 固定假 MAC让 baw 认为是不同机器，会话互不覆盖
登录态-v ./wallets/walletN/baw:/root/.baw每个钱包一份独立会话文件，容器重建也不丢
服务入口-p 127.0.0.1:(8787+N):8787一个钱包一个端口，全部只绑本机

钱包 1 为什么跑本机

本机网卡已经是「一台设备」，正好给第一个账号用，省一个容器。它直接读根 .env 的 WALLET_LABEL / WALLET_ADDRESS / LIVE_TRADE。

登录流程（扫码，5 分钟有效）

# 钱包 1
baw --json auth signin                         # 拿 urlForWeb + pairingCode
baw --json auth verify --qrCodeId <id>         # 轮询到 SUCCESS

# 钱包 N（N≥2）
docker exec tmtn-walletN baw --json auth signin
docker exec tmtn-walletN baw --json auth verify --qrCodeId <id>

卡片上的「登录」按钮做的就是这件事：它把 urlForWeb 和配对码取出来给你，浏览器打开链接就是二维码页，用对应币安账号的 App 扫。

地址锁定（防扫错账号）

每个钱包登录后把地址写死：钱包 1 进 .env 的 WALLET_ADDRESS，2–7 进 wallets/walletN/address。后端启动时比对实际地址与锁定值，不一致就拒绝下单——这样「不小心用 A 号的钱包下了 B 号的单」不会发生。

备注存在哪

wallets/labels.env，一行一个 WALLET_LABEL_N=备注。它被三个地方同时消费：容器环境变量 WALLET_LABEL、主后端的 WALLET_PEERS 列表、页面标题。所以改一次，列表、页头、下单选择里全变。

容器要出网（国内网络必须做）

Clash 只监听 127.0.0.1:7890，容器直连会被墙。链路是：

容器 → 172.31.0.1:17891（VM socat）→ 127.0.0.1:17890（ssh -R 反向隧道）→ 本机 Clash 7890

容器里注入 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY + NODE_USE_ENV_PROXY=1（Node 的 fetch 才认这三个变量）。重启机器后先跑 scripts/wallet-net.sh up。

加第 N 个钱包

scripts/wallets.sh add 8 新钱包        # 端口 8795、独立 MAC、独立 baw 目录、写好备注
scripts/wallets.sh signin 8            # 扫码
scripts/wallets.sh lock                # 锁地址

核心配置全在 wallets/walletN/docker-compose.yml，由 scripts/add-wallet.sh 生成，改 MAC 等于换设备（会要求重新登录），所以 MAC 定下别动。

新建钱包

每个钱包 = 一个独立容器（独立 MAC + 独立登录目录），端口自动 = 8787 + 序号，只绑本机。
