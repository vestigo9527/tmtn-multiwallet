# 本机 7 个 Agent 钱包 · 部署与运维手册

本机部署的 TMTN 多钱包环境：**钱包 1 跑本机进程，钱包 2–7 各跑一个 Docker 容器**，7 个钱包全部已登录、地址已锁定。以后要加第 8、9… 个钱包，照第 6 节的命令加即可。

---

## 1. 为什么必须「一个钱包一个容器」

签名全部走币安 Agentic Wallet CLI（`baw`），私钥在币安 App 里，本机只存会话。`baw` 判断「这台设备」用的是**网卡 MAC**：同一块网卡上登录第二个币安账号，会顶掉第一个账号的会话。所以：

| 钱包 | 隔离方式 | 走向 |
|---|---|---|
| 钱包 1 | 本机真实网卡 | `npm run live`，`http://127.0.0.1:8787` |
| 钱包 2–7 | 每个容器固定一个假 MAC（`02:…`） | 容器内 `npm run live`，端口 `127.0.0.1:8789–8794` |

容器只是一个「带独立 MAC、独立 `~/.baw` 的 Node 盒子」，不存私钥、不碰助记词。

## 2. 每天要用的命令

```bash
cd /path/to/TMTN

scripts/wallets.sh status              # 7 个钱包一览：备注 / 容器 / 后端 / 登录 / 实盘 / 地址
scripts/wallets.sh label               # 只看备注
scripts/wallets.sh signin 3            # 单个钱包扫码登录（打印链接 + 配对码）
scripts/wallets.sh signin             # 依次登录所有还没登录的
scripts/wallets.sh lock               # 把各钱包当前地址写死进配置（防扫错账号下错单）
scripts/wallets.sh live 3 4           # 让钱包 3、4 真实下单
scripts/wallets.sh quote 3 4          # 改回只报价
scripts/wallets.sh peers              # 打印/重建主后端的 WALLET_PEERS
```

页面入口（都只绑本机）：

- 钱包 1：http://127.0.0.1:8787
- 钱包 2..7：http://127.0.0.1:8789 … :8794

主后端页面右上角钱包菜单里能看到全部 7 个（来自 `.env` 的 `WALLET_PEERS`），下单可以指定用哪个钱包。

## 3. 备注（label）怎么工作

### 3.0 图形界面（推荐）

```bash
wallet-manager/ctl.sh start      # 或 start / stop / status / open
```

打开 http://127.0.0.1:8899 —— 7 个钱包一张卡片，直接改备注、按 Enter 保存；还能一键切「只报价 / 真实下单」、点「登录」取扫码链接、点地址复制。页面里的「多钱包原理」标签页就是这套隔离机制的说明。

右上角 **「＋ 新建钱包」** 就是加钱包的全自动流程：填序号（默认自动取下一个）+ 备注 → 勾选是否实盘、是否建完自动重启主后端 → 点创建。它内部依次做：`wallet-net.sh up` 检查出网通道 → 写备注 → 建容器（独立 MAC、端口 8787+序号）→ 同步 `WALLET_PEERS` → 重启主后端 → 直接给出扫码链接和配对码。实测约 3 秒（镜像已缓存时）。

### 3.1 命令行

备注存在 `wallets/labels.env`，一行一个：

```
WALLET_LABEL_1=demo1.ai
WALLET_LABEL_2=demo2.ai
...
```

改备注：

```bash
scripts/wallets.sh label 3 主号-打新      # 钱包 3 改叫「主号-打新」
```

- 钱包 1：写进根 `.env` 的 `WALLET_LABEL`，**重启主后端**生效。
- 钱包 2–7：写进该容器的 `WALLET_LABEL` 环境变量，命令会自动 `docker compose up -d` 重建容器，**登录状态在 `wallets/walletN/baw`，不会丢**；同时重写 `WALLET_PEERS`，主后端重启后跟着变。
- 备注会出现在：各钱包页面标题、主后端钱包列表、`scripts/wallets.sh status`、「参与下单」的选择列表。

只想看：

```bash
cat wallets/labels.env
scripts/labels.sh get 4        # 单取一个
```

## 5. 出网代理通道（容器能上币安的前提）

本机 Clash 只监听 `127.0.0.1:7890`，colima 虚拟机里的容器直接连 `binance.com` 会超时。解决链：

```
容器 → 172.31.0.1:17891（虚拟机 socat）→ 127.0.0.1:17890（ssh -R 反向隧道）→ 本机 Clash 127.0.0.1:7890 → 外网
```

容器里已经内置：

```
HTTP_PROXY=http://172.31.0.1:17891
HTTPS_PROXY=http://172.31.0.1:17891
ALL_PROXY=http://172.31.0.1:17891
NODE_USE_ENV_PROXY=1        # Node 22/24 的 fetch 才认这几个环境变量
NO_PROXY=localhost,127.0.0.1,::1
```

管理：

```bash
scripts/wallet-net.sh up       # 开机/重启后先跑这个（幂等）
scripts/wallet-net.sh status   # 隧道 / socat / 网络 / 容器出网自检
scripts/wallet-net.sh down
```

`WALLET_PROXY` 记在根 `.env` 里，`add-wallet.sh` 建容器时读它。

## 6. 以后加钱包（已实测）

### 6.0 页面一键新建（推荐）

打开管理台 → 右上角「＋ 新建钱包」→ 序号自动填好 → 写备注 → 创建。建完直接给扫码链接 + 配对码；扫完点右上角「锁定地址」，把新地址写死进配置。

### 6.1 命令行

```bash
scripts/wallets.sh add 8 新钱包-打新     # 建容器（端口 8795 + 独立 MAC + 独立 baw 目录 + 备注）
scripts/wallets.sh signin 8              # 用第 8 个币安账号扫码（二维码 5 分钟有效）
scripts/wallets.sh lock                  # 把地址写死
# 重启主后端让 WALLET_PEERS 生效：
kill $(lsof -ti tcp:8787); nohup npm run live > data/live.log 2>&1 &
```

要点：

- 序号接着往后排（8、9、10…），端口自动 = `8787 + 序号`，只绑 `127.0.0.1`。
- 只想要「只报价」的钱包，别加 `--live`，加完默认就是只报价。
- 加之前先 `scripts/wallet-net.sh up`，否则容器扫码会 `REQUEST_TIMEOUT`。
- `scripts/wallets.sh status` 会自动发现新序号（不用改任何变量）。
- 删钱包：`docker compose -p tmtn-wallet8 -f wallets/wallet8/docker-compose.yml down && rm -rf wallets/wallet8`，
  再从 `wallets/labels.env` 删掉 `WALLET_LABEL_8=`，最后 `scripts/add-wallet.sh --peers --write-env`。

## 8. 踩过的坑（都已修）

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器里 `getaddrinfo EAI_AGAIN www.binance.com` | colima 虚拟机 `/etc/resolv.conf` 空，Docker 报 `NO EXTERNAL NAMESERVERS DEFINED` | 虚拟机里写入 `223.5.5.5/8.8.8.8/1.1.1.1`，并在 `~/.colima/default/colima.yaml` 加 `dns:` 段，重启不丢 |
| 容器里 `Connect Timeout Error (www.binance.com:443)` | Clash 只监听 `127.0.0.1`，容器直连被墙 | 走第 5 节的 ssh -R + socat 通道，容器内置 `HTTPS_PROXY` + `NODE_USE_ENV_PROXY=1` |
| `baw` 在容器里报 `UNDICI-EHPA Warning` 把 JSON 吃掉 | 警告走 stderr，脚本 `2>&1` 后 `JSON.parse` 失败 | 脚本改成 stdout/stderr 分开重定向（`signin-all.sh` 已处理） |
| `scripts/add-wallet.sh: NAME（: unbound variable` | C.UTF-8 locale 下 `$VAR（` 被当成变量名 | 所有脚本里变量后接全角标点一律写 `${VAR}` |
| 二维码过期 | 币安登录码只有 5 分钟 | `scripts/signin-all.sh` 每轮重开；单钱包 `scripts/wallets.sh signin N` 重开 |
| 两个钱包地址一样 | 扫错账号，同一个币安账号登了两次 | `scripts/wallets.sh lock` 会报「地址重复」，用 `signin N` 重扫那个钱包 |
| 主后端日志刷 `provider destroyed; cancelled request` | 上游 `WsLogs` 断线重连时的 pending 订阅被拒 | 不影响行情（RPC 走 HTTP），`chainSubs.connected=true` 即正常，可忽略 |
| **手机退出登录后，后台点「登录」、扫码也确认了，状态一直不更新** | `baw auth signin` 只负责**发一张二维码**，真正把登录写进本机的是 `baw auth verify --qrCodeId <id>`，它是**阻塞长轮询**，不挂就永远不落地。管理台早期版本只发码、没挂 verify | 管理台已修（`signinJobs` 常驻 verify + 过期兜底 + `AUTH_REJECTED` 自动换码）；命令行手动重登见 8.1 |
| 连续点「登录」几次后 `baw` 报 `SERVICE_ERROR / System abnormality` | 取码太勤被币安限流 | 停手等 1–2 分钟再取 |
| `baw auth verify` 一直回 `AUTH_REJECTED` / "QR code does not exist or expired… restart the log in process"，换多少张新码都不行（冷却、重启管理台都无效） | 币安侧认为这台设备上一次登录流程还没收尾。**只要中途杀掉过 verify、或反复重新取码，就会进入这个互锁** | 先 `baw auth signout`（容器：`docker exec tmtn-walletN baw --json auth signout`）清掉残留流程，等 1–2 秒再取新码 + 立刻挂 verify。管理台已内置：只在未登录时才自动 signout 重置 |

### 8.1 重新登录某个钱包（手机退出登录之后）

关键：**取码和 verify 必须成对**，取完码后 verify 要一直挂着等你扫。

钱包 1（本机）：

```bash
cd TMTN
baw --json auth signin            # 拿到 qrCodeId / urlForWeb / pairingCode（5 分钟有效）
# 立刻另开一个终端（或加 &）挂着它，直到你在手机上确认：
baw --json auth verify --qrCodeId <上一步的 qrCodeId>
```

钱包 N（容器，N=2..7）：

```bash
docker exec tmtn-walletN baw --json auth signin
docker exec tmtn-walletN baw --json auth verify --qrCodeId <qrCodeId>
```

看到 `{"success":true,"data":{"status":"SUCCESS"}}` 就是落地了，随后：

```bash
baw --json wallet status        # 期望 CONNECTED
curl -s http://127.0.0.1:8787/api/wallet-info   # 期望 auth:"ok"
```

最省事还是用管理台（页面点「登录」）：它会在新标签页里给二维码，扫码确认后主页面自动变「已登录」。它内部走的就是 `scripts/qr-session.sh`，命令与上面完全一致，只是放在独立进程里跑（原因见 8.2）。

### 8.2 `AUTH_REJECTED` 的真正原因：长驻进程直接 spawn `baw` 必被拒（重要）

**结论**：`10002004 AUTH_REJECTED QR code does not exist or expired… [351701]` 跟「刚退出登录」「币安限流」「冷却」**都没有关系**。真正的原因是：**由管理台这个长驻 node 进程自己去 `spawn('baw', …)` 取码时，币安侧一定判定这张码无效**；同样的命令换一个独立的 bash 进程去跑，每次都成功。

同一分钟内的三组对照（都是一模一样的 `signout → sleep 3 → signin → verify`）：

| 发起方式 | 结果 |
|---|---|
| 管理台点「登录」×4（18:43–18:45） | 每次出码后 **1 秒内** `AUTH_REJECTED` |
| 命令行 `bash` 复刻同样步骤（18:46:32） | 出码 `3ZFp1zHF`，verify 正常挂着 ✅ |
| 短命 node 脚本用 `execFile` 复刻（18:46:52） | 出码 `2AjCoS3K`，verify 正常挂着 ✅ |

排查过的排除项：`which -a baw` 只有一份（`@binance/agentic-wallet@1.12.0`）；管理台进程的 `PATH`/`HOME`/`LANG`/代理变量与命令行**逐键比对完全一致**；`cwd` 相同；不存在第二份 `~/.baw`。

**所以现在的做法（已落地）**：取码不放在管理台里做了，交给 `scripts/qr-session.sh` 在**独立后台进程**里跑，管理台只读文件：

```
wallets/signin/N.json     {urlForWeb, pairingCode, qrCodeId, expireAt, pid}
wallets/signin/N.result   {status:"SUCCESS"|"FAILED", raw, at}
```

管理台 `POST /api/signin` 的流程：判会话（可用就直接回「已登录」，不动会话）→ 有未过期活码就复用 → 否则 `spawn('bash', qr-session.sh N)`（`detached:true` 脱离父进程）→ 轮询 json 最多 25 秒拿链接。实测 **5 秒出码**。

**kill 掉 verify 的纪律仍然成立**：verify 一旦挂上就别杀，杀了币安侧流程悬空，之后只能靠 `baw auth signout` 重置。`qr-session.sh` 里没有一处 kill。

### 8.3 一条命令兜底登录：`scripts/relogin.sh`

手机端退出登录后，最省事的是这个脚本——它就是 8.2 那套正确顺序的固化版，也是 2026-11-01 实测唯一稳定成功的路径：

```bash
cd TMTN
bash scripts/relogin.sh 1      # 钱包 1（本机 baw）
bash scripts/relogin.sh 3      # 钱包 3（容器 tmtn-wallet3）
```

它会依次做：

1. `baw --json wallet status` —— 已经是 `CONNECTED` 就直接退出，**不动你的会话**；
2. `auth signout` 清残留流程，停 3 秒；
3. `auth signin` 取码，打印二维码链接 + 配对码 + 剩余秒数；
4. 前台挂 `auth verify` 等扫码，成功后打印 `✓ 登录成功：0x…`。

也可以放后台、把链接发给手机：

```bash
nohup bash scripts/relogin.sh 1 > /tmp/relogin1.log 2>&1 &
sleep 15 && sed -n '1,12p' /tmp/relogin1.log
```

### 8.4 事故记录：自动重试把刚登录成功的钱包踢下线（2026-11-01）

**现象**：手机扫码、`verify` 返回 `SUCCESS`、`/api/wallet-info` 已经是 `auth:"ok"`，一分钟后自己变回 `logged_out`，而且管理台日志里没有任何 signout 记录。

**根因**：管理台给「被拒」的作业排了一个冷却结束后自动重试的定时器，重试走的是强制分支，而代码里 `force` 把**会话检查也一起跳过了**：

```js
if (!opts.force) {                  // ← force 时整段跳过
  const st = await sessionState(slot);
  if (st.ok) return { ok: true, already: true, ... };
}
await bawExec(slot, ['--json','auth','signout']);   // 于是对着刚登录好的会话 signout 了
```

**修复**：任何路径都先查会话，`force` 只允许跳过「复用旧码」和「冷却等待」，绝不跳过登录态检查；如果查到 `CONNECTED`，顺手把残留的 `waiting` 作业标成 `success`：

```js
{
  const st = await sessionState(slot);
  if (st.ok) { /* 复用，不 signout */ return { ok:true, already:true, address: st.addr }; }
}
```

**教训**：

- 自动重试、定时任务这类「无人监督」的路径，破坏力比手动操作大一个数量级：手动至少你在看日志。
- 任何会改写会话状态的动作（`signout` / 重建容器 / 重启主后端），前面必须有一次状态读取做闸门。
- 不要把「币安侧正常时序」包装成「冷却」甩给用户：手机退出登录后首张码必被拒，正确做法是**静默 60 秒后自动换码**（最多 3 次），界面上只显示「二维码准备中」，而不是让用户盯着倒计时等。凡是让用户等待的提示，先确认那是系统约束还是自己的实现缺陷。

### 8.5 页面扫码登录（新标签页 + 二维码）

点卡片上的「登录」：

- **已登录** → 只弹提示「钱包 N 已登录 · 备注 · 0x…」，不发码、不 signout；
- **未登录** → 立刻 `window.open('/qr?slot=N')` 开新标签页：
  - 标签页 1.5 秒轮询 `/api/session?slot=N`，先显示「正在取码…」，出码后变成二维码 + 大号配对码 + `等扫码 · 剩余 4:43`；
  - 手机币安 App「扫一扫」确认 → 标签页变「已登录 ✓」；
  - 主页面同时每 2.5 秒查 `/api/state`，卡片跟着变「已登录」，并把标签页关掉。

二维码是**本地生成**的（`brew install qrencode`，服务端 `qrencode -t SVG` 把 `urlForWeb` 画成 SVG，走 `/api/qr.svg?slot=N`），不依赖任何外网图床。`uni-qr` 链接本身在桌面浏览器里只会跳转到 App 下载页，所以必须自己画码。

没装 qrencode 时页面会显示「还没有二维码」；`brew install qrencode` 后刷新即可。

## 9. 安全边界

- 所有容器端口、主后端端口都只绑 `127.0.0.1`，外网访问不到。
- 主后端与各容器的 `TMTN_API_TOKEN` 必须一致（≥32 位），否则订单转不过去。
- 私钥只在币安 App 里；本机 `wallets/walletN/baw/` 只是会话凭据，权限 700，已加 `.gitignore` 级别的目录不提交。
- 默认全部「只报价」（`LIVE_TRADE=0`）。要真实下单得显式 `scripts/wallets.sh live N`，并且页面里还要打开该钱包的「参与下单」。
- 每个钱包都锁定了地址（`WALLET_ADDRESS`），扫错账号的钱包会被主后端拒绝下单。
